## 振り返り（KPT）

### Keep
- 契約を書く前に、補完の場所・既存の並べ替えの検証順・カードのDOM構造を読んだ。実装中の「specと既存コードの食い違い」は0件だった（前ボルトの反省が効いた）。
- 「読み込みだけでは保存しない」のように仕組みに依存する契約は、委譲プロンプトで「現状の仕組みで成り立たないなら実装せず報告」と指定した。
- レビュアー全員が未確認とした点（旧版互換）を、オーケストレーターが自分で確認した。

### Problem
- `[testing]` 旧版互換は、新版のencode出力の検査とコードの読解に留まり、旧版のコードで実際に読み込む実行確認ができていない。
- `[tdd]` 画面の「成功後に再取得」のテストが、テスト側でキャッシュを書き換える作りで、実装を消しても通る状態だった。
- `[boundary]` 型に必須項目を足すと、別レイヤーのテストfixtureへ修正が波及する。担当範囲の例外として事前に許可が要った。
- `[gate]` 機能が要件定義に無い追加だったが、Gate 1では要件定義の更新（PRJ-10）を明示していなかった。

### Try
- 保存データの形を変えるボルトでは、旧版のStoreで新Snapshotを読み込む実行確認の手順（FIX-rollback-compatibilityのharness）をテストケースに入れる。
- 「成功後に再取得」を検証するテストは、fetchスタブの応答だけを差し替え、キャッシュを直接書き換えない。
- 共有型に必須項目を足すタスクは、委譲時に「他レイヤーのfixtureへの最小追記を許可」と範囲を明記する（今回は明記して機能した）。
- 要件に無い機能追加は、Gate 1で要件定義の追加行も提示する。
