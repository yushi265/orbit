# FEAT-issue-hierarchy-list: Issue一覧の親子インデント表示

## 概要

親Issue・Sub-issueの関係（`parentId`）はIssue詳細でしか見えず、一覧（List）では手がかりが無い。一覧で子を親の直下に字下げして並べ、親子関係をひと目で分かるようにする（要件ISS-11「親子の進捗を表示する」の一覧側）。

## 対象範囲

- 対象レイヤー: [ui](./ui.md)
- Issues一覧とProject詳細のIssue一覧（共通の`IssuesView`）のList表示
- 子の字下げ、親の開閉、親の行の子完了数バッジ、親が一覧に無い子への親名の表示
- 手動並べ替え（ドラッグ / Alt+↑↓）を兄弟の中に限定する

## 対象外

- Board表示、Cycle画面の一覧、Home・Searchの一覧
- 一覧での親の付け替え（Issue詳細の既存操作のまま）
- サーバー・共有契約・URL状態・保存される表示設定の変更
- 開閉状態の端末間同期

## ユニット計画

単一ユニット。

## 受け入れ基準（AC）

- [x] **AC-1**: List表示では、一覧に表示されているIssueのうち親も一覧に表示されているものを、親の直下に字下げして並べる。孫以降も同じ規則で入れ子にし、字下げの見た目は3段で頭打ちにする。
- [x] **AC-2**: 選択中の並び順は、同じ親を持つ兄弟どうし（最上位どうしを含む）に適用する。どの並び順でも、子は親の直下にまとまる。
- [x] **AC-3**: 表示中の子を持つ親の行は、開閉ボタン（`aria-expanded`つき、名前「子Issueを折りたたむ」/「子Issueを展開する」）を持つ。閉じると、その親の子孫の行を表示しない。初期状態はすべて開いている。
- [x] **AC-4**: 閉じた親はこの端末のlocalStorage（キー`orbit.issues.collapsedParents`）に保存し、再読込後も閉じたままにする。localStorageが使えない・値が壊れている場合は、すべて開いた状態で表示する。
- [x] **AC-5**: 子を持つIssueの行は、直下の子の完了数バッジ「完了数/母数」を表示する。数え方はIssue詳細の子の進捗と同じ（母数は直下の子の総数でCanceledも含み、Completedカテゴリを完了と数える）で、フィルターで隠れている子も数える。直下の子が0件のときはバッジを表示しない。
- [x] **AC-6**: 親を持つIssueのうち、親が一覧に表示されていないものは、字下げせず最上位に並べ、タイトルの下に「↳ 親のID 親のタイトル」を表示する。親が一覧のデータに無い場合は何も添えない。
- [x] **AC-7**: 並び順が「手動」のとき、ドラッグとAlt+↑ / Alt+↓による並べ替えは、同じ親を持つ表示中の兄弟の間でだけ行える。兄弟でない行へのドロップと、兄弟の端を越える移動は何も起こさない（並べ替えAPIを呼ばない）。
- [x] **AC-8**: 「全選択」は表示中の行（閉じた親の子孫を除く）だけを選択する。行ごとの選択・一括操作・Issueを開く操作・行内のStatus / 重要度 / Project / 期限の変更は従来どおり動く。
- [x] **AC-9**: Board表示と、親子関係を持たないIssueだけの一覧は、表示と操作が従来と変わらない。

## アーキテクチャ / レイヤー間フロー

表示層のみ。`IssuesView`が受け取る絞り込み・並び替え済みの`issues`と、絞り込み前の`allIssues`から、純粋関数で「表示する行の列」（Issue・深さ・子の有無・進捗・親名）を組み立てて描画する。並べ替えは既存の`POST /api/v1/issues/reorder`をそのまま使う（位置は平坦な`position`のまま。兄弟どうしの相対順だけが表示に効く）。

## エラー・ログ方針（横断サマリ）

| シナリオ | ui |
|---|---|
| localStorageの読み書き失敗・不正な値 | 例外を握りつぶし、すべて開いた状態で表示する。ログは出さない |
| 親子データの循環（サーバーが防止済みだが防御） | 訪問済みで打ち切り、該当Issueを最上位として表示する |
| 並べ替えの失敗 | 既存のエラー表示のまま |

## 既存実装との関係（再利用 / 差分 / 衝突）

- 再利用: `sortIssues`の結果（`issues`は並び替え済み）、`calculateCycleMetrics`（`src/shared/cycle-workspace.ts`。Issue詳細の子の進捗と同じ計算）、`beforeIssueIdForDrop`、`IssueRow`、既存のlocalStorage利用（`orbit.issues.showCompleted`と同じ読み書きの形）。
- 差分: 行の列の組み立て（新規の純粋関数）、`IssueRow`の字下げ・開閉・バッジ・親名、並べ替えの兄弟限定、全選択の対象。
- 衝突: なし。CYC-14の並べ替え契約（`beforeIssueId`での挿入）は変えない。兄弟でない行への操作をUIで止めるだけ。
- codekb照合: 「Reorder FocusはKeyboardで実際に移動した場合だけ記録」— 兄弟の端で何もしない場合は移動なしとして既存の扱い（`onMove`がfalseを返す）に合わせる。

## 判断根拠 / 未決事項

- 並び順を兄弟どうしに適用する（Gate 1・2026-10-05）: 並び順によって親子が離れる問題を避けるため。
- 親が非表示の子は最上位＋親名（Gate 1で選択）: 絞り込み結果に条件外の行を混ぜないため。
- 開閉はlocalStorage（Gate 1で選択）: サーバーの表示設定に足すと契約変更になるため。
- 位置は平坦なまま兄弟限定にする理由: 親子で位置を分けるとデータの形が変わりTier 1になる。兄弟の相対順だけを使えば既存のAPIで足りる。
- バッジは隠れている子も数える理由: フィルターで数字が変わると進捗として読めないため。Issue詳細の表示とも一致する。
- バッジの母数にCanceledを含める理由: Issue詳細の「子Issue 完了数 / 総数 完了」が`calculateCycleMetrics`の`total`（Canceledを含む）を表示しており、一覧と詳細で数字を揃えるため。当初のspecは詳細の数え方を確かめずに「Canceledを除く」と書いており、実装前にimplementerの指摘で訂正した（2026-10-05）。
- 受け入れるトレードオフ: 全選択が「表示中の行だけ」になる（閉じた親の子は選ばれない）。見えていない行を一括操作しないための変更。
- 親子の無い一覧にはスペーサーを入れない理由: AC-9（従来と変わらない）。最初の実装は全行に開閉ボタンぶんの空きを入れており、ブラウザ確認でタイトルが24px右へずれると分かったため、開閉ボタンを持つ行がある一覧だけ空ける形へ変えた。
- サーバー描画との不一致（hydration）の懸念は不採用: ルートにloaderが無く、Bootstrapの取得が終わるまで読み込み表示だけを描画するため、一覧はサーバーでは描画されない。localStorageは一覧の初回描画時に読む。
- 確認方法: jsdomのテストに加え、ブラウザ（PC幅・375x812、ライト / ダーク）で、3世代の字下げ・開閉と再読込後の復元・絞り込み時の親名・タイトルと期限の左端の揃いを確認した。実際のドラッグ操作とiPhone実機は未確認。
- 未決事項なし。
