## 振り返り（KPT）

### Keep
- implementerがspecの矛盾を見つけた時点で実装を止めて報告した（委譲プロンプトに「食い違ったら実装せず報告」と具体的な確認点を書いていた）。
- 表示層の変更をブラウザで触って確認し、テストでは見えないずれを3点拾った。
- レビュー指摘は採用前にコードで裏取りし、誤りは理由つきで棄却、正しいものは再レビューまで回した。

### Problem
- `[spec]` 「既存の表示と同じ」と書きながら、既存の表示を読まずに数え方を書いた（AC-5）。
- `[spec]` 表示の絞り込み（閉じる）と選択・一括操作の関係を、specで決めていなかった。全選択だけ決めて、選択済みの行が隠れる場合を落とした。
- `[tdd]` 並べ替えのfixtureが、平坦な位置の並びと階層の並びが一致する単純な配置だけだった。
- `[testing]` 「従来と変わらない」（AC-9）を、DOMに要素が無いことだけで確認し、位置のずれを見ていなかった。

### Try
- specで「既存の○○と同じ」と書くときは、その既存実装のファイル:行を読んでから具体値を書く。
- 表示を絞り込む機能（閉じる・フィルター）を足すときは、選択・一括操作・フォーカスが隠れた行をどう扱うかをspecの状態設計に必ず入れる。
- 並べ替えのテストは、最初から「兄弟の間に他の要素が挟まる」配置で書く。
- 表示層のボルトは、Stage 5のブラウザ確認で「変わらないはずの画面」も開いて位置を見比べる。
